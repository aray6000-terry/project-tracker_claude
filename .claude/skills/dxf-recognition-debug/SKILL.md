# DXF 辨識異常診斷與修正

對象：平台前端 `dxf-core.js`（純函式，Node 與瀏覽器共用）。修正完要把 `CORE_VERSION` 加一，舊專案才會提示重新分析。

## 步驟
（輔助腳本在本資料夾，於 repo 根目錄執行：`node .claude/skills/dxf-recognition-debug/run_analyze.js <檔.dxf>`、`node .claude/skills/dxf-recognition-debug/inspect_title_neighbors.js <檔.dxf> "B2F 統計數量表"`）
1. **在 Node 重現**：`D=require('./dxf-core.js'); r=D.analyze(D.decode(fs.readFileSync(f)).text,{})`，印 `r.warnings`、`r.tables`（key／x／y／rows）、`r.floors`。必須先重現出一樣的警告才改。
2. **看標題周圍的原始文字**：`D.parse(text).texts` 找出警告裡的標題，列出其下方約 14 倍字高、左右 45 倍字高內的所有文字（x,y 相對標題、字高、內容）。重點看：欄位標題實際寫什麼、數量欄在哪、品名欄 x 在標題左或右。
3. **對照比對規則**（`方式一` 約 dxf-core.js 第 350 行起）：
   - 標題 regex 是否吃得下標題字樣（含「統計」位置）
   - `qh`（數量欄標題）、`dh`（品名欄標題）regex 是否涵蓋圖上寫法
   - `buildTable` 取品名欄的 x 範圍是否涵蓋
4. **在 table 建好後印出 key**（`DBG` 環境變數插 console.log）：若全部是「表N」，代表標題的樓層沒解析出來，是標題 regex 的問題，不是樓層配對的問題。
5. 修正後確認：警告歸零、`r.floors` 完整、每層數量合理（單層表與「3~13F」表的每層數量一致）。
6. `CORE_VERSION` +1，輸出 diff，記錄到專案文件「DXF平台批次測試」。

## 常見原因對照表
| 警告 | 實際原因 | 修正 |
|---|---|---|
| 找到「XF 統計數量表」但讀不到欄位標題 | 品名欄標題寫「圖名」（或其他不在 說明／名稱／品名／項目／設備／器材／規格 的字，如「圖塊｜圖名｜數量」） | `dh` regex 加入該字 |
| 找到數量表但樓層全變「表N」、後來被平面圖標題硬配成錯一層 | 標題寫「B2F **統計**數量表」，標題 regex 的樓層群組吃進「統計」，樓層解析失敗 | 標題 regex 在數量前允許 `(?:統計)?` |
| 多層表（3~13F）整張沒讀到 | 品名欄比表名文字更靠左（表名不靠左對齊），欄位範圍從表名 x 起算而漏掉 | 品名欄左界改用 `min(表名中點, 品名欄標題x − 字高/2)` |
| 多層表數量讀成總數 | 表有「數量」（每層）與「總數量」兩欄，抓到後者 | 數量欄優先選不以「總」開頭者 |
| 平面圖附近找不到數量表（連鎖警告） | 上述任一原因使數量表沒建起來 | 先修數量表，再重跑，連鎖警告會消失 |
| 圖面中找不到「數量表」 | 同上，所有表都沒建起來；括號內「圖上含數量的文字」可看到標題的實際字樣 | 同上 |

## 判斷訣竅
- 警告裡「圖上含『數量』的文字」清單就是線索：有「B3F 統計數量表」、「數量」→ 標題與數量欄都在，缺的是品名欄或標題解析。
- 連續出現「附近找不到數量表」且圖上沒有符號 → 先找為什麼 tables 是空的，不要去調平面圖配對。
- 只要「表N」出現，就看標題 regex；只要 rows 為空，就看欄位範圍與欄標題。
- 不要為單一圖檔寫特例；改成通用規則，並確認不影響既有 99 專案測試結果（見專案文件「DXF平台批次測試_99專案」）。
